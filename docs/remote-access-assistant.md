# 远程访问助手

在玩家列表中私聊“远程访问助手”，发送设施的游戏内中文名称，或发送“菜单”后按编号选择。设施编号属于当前地图，换地图后应重新查看菜单。同名设施、包含多个设施的类别简称会返回候选编号，避免打开错误门店。

菜单按设施 ID 区分门店：食品店、饮料自动贩卖机、品牌商店、工业品商店和小锯木厂分别列出；同一门店的多个入口合并。船、载具租赁等依赖特定位置的设施不提供远程入口。仅列出客户端 4.0.25034 场景中的常驻启用设施，不包括季节性活动设施。

服务端复用已有私聊和个人消息协议，交易、修理与卖鱼继续由原有处理器完成。**打开客户端页面需要安装下面的可选客户端桥接模块；只更新服务端只能获得文字菜单。**

## Windows 客户端模块

支持 Windows x64 客户端 4.0.25034。该模块在本地单机接入完成后使用，本身不提供登录、连接路由或 Steam 初始化修复。

1. 在 Visual Studio 的 x64 Native Tools Command Prompt 中进入 `tools/remote-access-client`，运行 `build.cmd`。需要 Python 3 和 MSVC C++ 工具链。
2. 退出游戏，备份客户端目录内已有的同名 DLL。把 `out/winmm.dll` 和 `out/rf4_remote_winmm_system.dll` 放到 `rf4_x64.exe` 旁。不要覆盖其他模块提供的 `winmm.dll`；已有加载器可集成同目录的 `remote-assistant.h`。
3. 在客户端目录新建 `rf4-remote-access.ini`：

   ```ini
   [remote_access]
   enabled=1
   ```

4. 启动连接本地模拟器的游戏，私聊助手测试。日志为客户端目录的 `rf4-remote-access.log`。退出游戏后把开关改为 `0` 可禁用；卸载时恢复安装前的 DLL。

模块从当前已加载场景查找与所选设施 ID 对应的对象，调用既有页面入口。消息通过原来的发送回调发送一次，延迟到下一次 UI 消息处理时打开页面。客户端更新后若发送入口指令不匹配，模块会拒绝安装回调并记录日志。

设施定义在 `internal/gameserver/assets/remote_facilities.json`。变更定义后执行 `python tools/remote-access-client/generate_catalog.py` 同步客户端表，使用 `--check` 可检查两端是否一致。表内仅包含接口标识、短名称和分类，不包含客户端程序集、场景、美术资源或玩家数据。

## 验证

开发时可在同一 x64 工具终端运行 `build.cmd test`，核对发送回调、玩家 ID 判断、菜单歧义与多位数编号。服务端专项为 `go test ./internal/gameserver -run TestRemoteAssistant`。

- “菜单”名称、编号与当前地图一致；跨地图相同编号可指向不同设施。
- 输入设施名称与编号都能打开同一个门店；同名或多候选简称先列出选择。
- 至少验证一张含同类多门店的地图，分别打开两家并核对标题和货架。
- 其他玩家私聊不触发助手动作；物品不能发给虚拟联系人。
- 本模块只负责打开页面；各地图设施的购买、修理、位置限制仍遵循既有服务端实现。
